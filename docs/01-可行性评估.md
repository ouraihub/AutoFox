## 2. 为什么不移植提取器

yt-dlp 是两个经济性完全相反的部分粘在一起：

| | 规模 | 变更频率 | 性质 |
|---|---|---|---|
| 核心引擎 | 2.9 万行 | 低 | 有公开规范的工程代码 |
| 提取器 | 18.4 万行 / 940 文件 | 高（每日提交主体） | 站点前端的镜像，易腐 |

Python → Rust 约 1.5–2 倍行数，提取器移植量 **≈ 30 万行 Rust**，另需一个 JS 解释器（YouTube 签名解密所需，yt-dlp 内对应 `jsinterp.py` 39.2 KB）。

工作量不是决定性因素，**维护不对称**才是：

| 方案 | 站点改版后 | AutoFox 代码 |
|---|---|---|
| A 外部后端（进程契约） | 上游数小时~数天修复，用户换二进制 | 不动 |
| B 原生 Rust crate | 等上游 crate 或自己修 | 要改 |
| C 完整移植 | 从 yt-dlp 的修复里重新移植，永远，独自 | 要改 |

移植得到的是**没有上游的 fork**：代码拿到了，23,998 次提交沉淀的站点知识与每日流入的修复没拿到。

许可层面 yt-dlp 为 Unlicense（公有领域），移植不受限制。另需注意该仓库根目录存在 `.NO_AI/README.md`，明确禁止使用 LLM/AI 工具对其进行任何形式的贡献，并要求 AI agent 拒绝与该仓库交互。本设计因此不包含对其实现文件的逐行分析或转写；AutoFox 与 yt-dlp 的耦合点只有**公开的 CLI 契约**（`-J` 输出、退出码），不涉及内部实现。

**结论：不移植提取器。**

## 3. 为什么自研下载引擎

下载层依据公开规范，无需参照任何实现：

- **HTTP Range 分段并发 / 断点续传** — RFC 9110 §14
- **HLS** — RFC 8216
- **MPEG-DASH** — ISO/IEC 23009-1

这部分是 AutoFox 的核心资产：调度策略、并发上限、限速、`.part` 临时文件 + 原子 rename、失败重试、队列持久化与重启恢复。它们不随站点改版失效，且直接决定用户感知的产品质量（速度、稳定性、可恢复性）。

**结论：下载引擎、队列、UI 全部自研。**

## 4. 后端可替换性

Rust 生态已有可用的 YouTube 原生实现（crates.io 实测）：

```text
rustypipe             0.11.4    42,524 下载   YouTube/YT Music Innertube 客户端
rustypipe-downloader   0.3.1     9,284 下载   下载扩展
rustypipe-botguard     0.1.2     7,455 下载   Botguard 挑战 / PO token
dash-mpd              0.20.5   419,685 下载   MPEG-DASH MPD 解析
quick-m3u8             0.8.0     6,356 下载   HLS M3U8 解析
hls-transmux           0.2.1        314 下载   TS/fMP4 → MP4 转封装
```

一个信号：crates.io 上下载量最高的名为 `yt-dlp` 的 crate（2.8.3，42,178 下载）自我描述为 "with auto dependencies installation"——它是二进制包装器，不是重写。

因此**两种后端都可行**，但滞后风险不同：yt-dlp 覆盖 1800+ 站点、社区响应快；rustypipe 仅覆盖 YouTube 系、项目体量小。设计上不做二选一，而是把两者收敛到同一契约下并支持回退（见 [03-后端契约](03-后端契约.md)）。

## 5. 随包布局与依赖形态

外部可执行文件**随包分发，不依赖 PATH**：

```text
AutoFox/                          安装目录
├─ AutoFox.exe                    主程序
├─ yt-dlp.exe                     解析后端（与主 exe 同目录）
└─ lib/
   ├─ ffmpeg.exe                  合流
   └─ ffprobe.exe                 产物校验与诊断
```

运行期依赖形态：

| 组件 | 形态 | 是否需要 Python |
|---|---|---|
| `yt-dlp.exe` | PyInstaller 冻结，CPython 内置于 exe | **否** |
| `ffmpeg.exe` / `ffprobe.exe` | 静态构建，自带编解码器 | 否 |
| AutoFox 自身 | Rust 原生 | 否 |

**AutoFox 运行期零 Python、零 PATH 依赖。** uv（0.10.4）只在一种场景使用：开发者修改 yt-dlp 源码后，以 `uv run yt-dlp` 对源码树验证。该形态不进发布产物，见 [03-后端契约 §1.1](03-后端契约.md)。

路径解析优先级（[03-后端契约 §7.1](03-后端契约.md) 给出实现）：随包路径 → 用户在设置中指定的路径 → PATH（最后且可关闭）。默认不静默回落到 PATH，避免用户机器上的旧版本被意外使用。

## 6. 已知硬依赖与风险

| 项 | 说明 | 处置 |
|---|---|---|
| **ffmpeg** | DASH/YouTube 高码率为音视频分离流，必须合流。Rust 生态无可靠替代 | 随包置于 `lib/`；LGPL/GPL 合规见 [04 阶段 5.3](04-实施计划.md) |
| **PO token / 风控** | YouTube 附加 attestation，是持续对抗 | 交后端处理；AutoFox 不自建 |
| **后端 JSON 漂移** | yt-dlp 每日提交，输出字段会增删 | 反序列化全部 `#[serde(default)]`，禁用 `deny_unknown_fields` |
| **子进程注入** | URL 来自用户输入 | 数组传参 + `--` 终止符 + scheme 白名单 |
| **错误泄漏** | 后端 stderr 含完整 URL、有时含 cookie | 只进本地日志；IPC 错误载荷仅静态字段（沿用 AutoAnt `ipc.rs` 约定） |
| **版权与合规** | 下载工具的固有风险 | 首版不内置任何站点绕过；仅转发用户显式请求 |

## 7. 首版边界

**做**：单条与批量 URL 解析、格式选择、下载（直链/HLS/DASH）、断点续传、限速、队列持久化、ffmpeg 合流、后端可选可加、中英文 UI。

**不做**：云同步、登录账号体系、内置播放器、自建提取器、移动端、字幕翻译、转码（只合流不重编码）。
